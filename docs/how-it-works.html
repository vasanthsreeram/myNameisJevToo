A light walkthrough

The answer is already in the last position.

A causal model only looks backward. End the prompt where the answer belongs, read the next-token distribution, and you have a typed decision. Nothing is generated, and the weights are unchanged.

01

The mask is the whole trick.

Each row is a position. A cell lights only when that position is allowed to see it — the present, and everything before it. The clay cell is where we stop. Its logits are a distribution over the next token, computed without having seen a future that does not exist yet.

Put the state and the options in the context. The last position is the word Answer. We never sample a continuation. We read the row.

Lower triangle lights, then the read cell. Loops.

02

Frame the state, then stop.

Options are letters, each one token in most tokenisers: “ A”, “ B”, “ C”. The rubric sits on the line so the model is choosing described options, not bare identifiers. The prompt ends at Answer:.

04

Two numbers, two questions.

Raw is the probability of each letter in the full vocabulary. They do not sum to 1 — the rest of the vocab still holds mass. That remainder is the gate: did the model want to answer at all? Share divides by the option set only. That is the number to branch on.

05

One distribution, three types.

Choice takes the argmax. Noul reads P(yes) by name, not by position. Score is the expected level, so it can land between two rungs. HTTP confidence is peakedness, (n × max p − 1) / (n − 1). The library’s confidence is the winner’s share.

06

Same endpoint, your weights.

POST /v1/systemone takes state, model, and a map of questions. jev-latest is an alias for whatever you loaded. Answers come back under the same keys. Ask to observe, and you also get queue time, option mass, and a flag when a question has only two labels.

questions.topic: choice
questions.urgent: noul

07

The state is paid for once.

Questions in one request see the same state. On MLX, when those prompts share a long token prefix, that prefix is prefilled once and each question is a short continuation. The observe block reports shared_prefix_tokens so you can see whether the share happened.

08

Two labels can be a position.

On a small model, a yes/no question sometimes picks whichever label is written first, with the state and without it. The highlight below stays on the top slot while the words trade places. Four or five options give that prior somewhere to spread. The server marks every two-label question with binary_position_prior.

Swapping the words does not move the pick. That is the order trap from the binary flip test, drawn as motion so it is harder to miss.
